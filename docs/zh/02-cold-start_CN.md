## 一句话理解

> **冷启动 = 公司来了个新员工，啥履历都没有，怎么尽快给他派活、知道他擅长啥；同时餐厅推了新菜，没人点评，怎么让顾客试试。**
>
> 这两件事每天都在所有平台上**同时发生几百万次**。
>
> **TikTok 每天上传 1.2 亿条新视频** = 每秒 1,400 道"新菜上线",
> **抖音每天注册数百万新用户** = 每秒几十个"新员工入职"。
>
> **冷启动不是"偶发问题"，是推荐系统的日常呼吸。**

---

## 1. 为啥冷启动是头号难题

| 真实场景 | 冷启动表现为 |
|---|---|
| 新员工第一天上班，HR 啥都没记录 | 模型不认识这个用户，无法预测他的偏好 |
| 餐厅新加一道菜，没人点评 | 模型不知道这道菜好不好，不敢推 |
| 整个连锁餐厅刚开业 | 全平台都是新菜、新顾客，连"热门兜底"都没数据 |

### 三个"必须解决"的理由

1. **量太大**：抖音、快手、小红书每天新增的物品和用户都在百万级，**每秒都在产生**
2. **越早决定越关键**：新员工/新菜的**前几次反馈**会决定模型对它的"第一印象"，错了很难翻盘
3. **影响业务核心**：
   - **创作者公平性**：新创作者必须有曝光机会，否则平台会变成"老创作者寡头"
   - **用户留存**：新用户前 3 次刷的体验决定他会不会留下来

---

## 2. 三种"新"

| 类型 | 餐厅类比 | 推荐术语 | 例子 |
|---|---|---|---|
| 新用户 | 新顾客第一次进店 | User cold start | 抖音/小红书的注册用户 |
| 新物品 | 新菜刚上线 | Item cold start | TikTok 新视频、Pinterest 新 pin |
| 新平台 | 整个新店开业 | System cold start | Netflix 1998 年创立时 |

每种"新"的本质都是同一个问题：**没有历史数据 → 协同过滤瞎了 → 必须靠别的信号兜底**。

但具体怎么兜底，三种情况差别很大，下面分开讲。

## 3. 新员工怎么破冰 — 用户冷启动

新员工入职第一天，HR 有 5 种破冰策略：

### 3.1 主动问 — Onboarding(喜好问卷)

最直接的方法：**让用户自己说**。

| 平台 | 怎么做 |
|---|---|
| **Netflix** | 注册时**必选 5 部喜欢的电影** |
| **Spotify** | 注册时勾选 **5 个艺人 + 5 个流派** |
| **小红书** | 注册时选 **5 个兴趣标签**（穿搭 / 美食 / 旅行 / 数码 / 母婴 ...） |
| **YouTube Shorts** | 注册时选 **8 个感兴趣的频道类型** |
| **Pinterest** | 注册时选 **5+ 个兴趣 board**(家居 / 时尚 / DIY ...) |

**优点**：用户主动表态，信号强、干净。
**缺点**：用户嫌烦，30% 用户会跳过；选了之后的真实行为可能跟选的不一致。

### 3.2 旁敲侧击 — Demographics

如果用户不愿意填问卷，**只用注册信息（性别 / 年龄 / 地区）做粗略推断**。

```
22 岁 / 男 / 北京 → 默认画像：科技 + 游戏 + 电竞
35 岁 / 女 / 上海 → 默认画像：母婴 + 美食 + 家居
```

**优点**：零成本，注册就有。
**缺点**：精度极低，刻板印象重。**Netflix 早期非常依赖**，后来基本不用了。

### 3.3 借鉴老员工 — Look-alike(相似用户借画像)

**核心思路**：新员工没数据 → 找几个"看起来很像"的老员工 → 借他们的画像。

| 平台 | 怎么找"相似"老员工 |
|---|---|
| **抖音 / 快手** | 用**手机号 + 设备型号 + 地理位置 + 注册时间**这些非行为特征查"相似 100 人" |
| **Facebook / 微信** | 用**社交图**：你朋友喜欢的，你大概率也喜欢 |
| **Pinterest** | 用**邮箱 / Gmail 历史 + 浏览器历史**（早期）做 look-alike |

**优点**：能立刻给出个性化推荐。
**缺点**：**容易刻板印象锁死**——看了 3 个二次元 → 模型把你打成"宅男" → 接下来只推动漫，永远翻不了身。

### 3.4 让新员工试任务 — Bandit 探索

**核心思路**：故意给新员工**几个不同类型**的任务，**根据他完成情况快速更新画像**。

| 算法 | 大白话 |
|---|---|
| **ε-greedy** | "90% 推热门 + 10% 随机试" |
| **UCB** | "优先推'不确定性高'的（信息量大）" |
| **Thompson Sampling** | "按'可能很好'的概率推" |

#### 真实案例

| 平台 | 做法 |
|---|---|
| **YouTube** | 新用户前几次刷，**ε=0.2 的 ε-greedy**:80% 推热门，20% 随机试 |
| **快手"双流量池"** | 新用户先进**探索池**，画像稳定后转**主流量池** |
| **Yahoo News(2010 年经典实验)** | Thompson Sampling 替代固定推荐 → **CTR +12.8%** |
| **小红书** | 新用户前 50 篇笔记**多样性强制提升**（不让单一兴趣占比 > 30%） |

**最关键的理念**：**新员工的前 50 次曝光是"投资"，不是"获利"**。这 50 次的目的是**收集信号**，不是最大化点击率。

### 3.5 五种策略怎么组合

```
新用户进来
    │
    ▼
┌─────────────────────────────────────────┐
│ Step 1: 注册阶段 → Onboarding 问卷       │  (30% 用户跳过)
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ Step 2: 第 1 次刷 → Look-alike + Demo    │  (借画像，给个初版)
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ Step 3: 前 50 次刷 → Bandit 探索         │  (主动收集信号)
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ Step 4: 画像稳定 → 进入常规推荐管线        │  (转主池)
└─────────────────────────────────────────┘
```

## 4. 新菜怎么上线 — 物品冷启动

新菜上线，餐厅有 4 种"推菜"策略：

### 4.1 强制曝光(forced exposure budget)

**核心思路**：**主动赔本**给新菜分配最低曝光预算，必须把它推到 N 个用户面前看效果。

| 平台 | 强制曝光预算 |
|---|---|
| **TikTok** | 新视频前 **500 曝光**是强制分发 |
| **快手"小流量测试"** | 新视频先给 **500 ~ 2,000 人**，根据完播率/点赞率决定要不要 ramp up |
| **YouTube Shorts** | 新视频 **24h 内有保底曝光预算**，根据初期反馈决定是否进入主流量池 |
| **小红书** | 新笔记 **24h 内有"创作者保护流量"** |

**为啥要"赔本"**？因为**不曝光就永远没数据 → 永远学不到这个新菜好不好**。这 500 次曝光是"探测成本"。

### 4.2 借作者的传播力 — 关注/粉丝召回

**核心思路**：新菜没人吃过，但**做这道菜的厨师有粉丝** → 先推给老粉丝。

| 平台 | 做法 |
|---|---|
| **B 站 / YouTube** | 新视频先推给**订阅了该频道**的人 |
| **小红书** | 新笔记先推给**关注作者 + 相似兴趣**的用户 |
| **快手 / 抖音** | 新视频借作者的**关注关系链**做第一波分发 |

**优点**：**对老作者基本不算冷启**——老作者的新视频立刻就有几千到几万的初始曝光。
**遗留问题**：纯粹的新作者+新视频还是冷启。

### 4.3 借内容相似度 — 内容召回

**核心思路**：新菜没人吃过，但**新菜跟某个老菜很像** → 推给喜欢老菜的人。

| 平台 | 做法 |
|---|---|
| **Pinterest** | 新 pin 用 **PinSage 图嵌入**（自研 GNN）找视觉相似的存量 pin → 借其用户 |
| **抖音 / TikTok** | 用 CV 识别新视频内容（食物/穿搭/旅行 ...）→ 找同类老视频的用户 |
| **小红书** | 新笔记用多模态 embedding 找相似存量笔记 |
| **YouTube** | 新视频用标题 + 描述 + 缩略图找语义相似的存量视频 |

→ 这就是为啥 **[`03-item-understanding.md`](../en/03-item-understanding.md)(物品理解)是冷启动的命脉**。**没有物品理解 → 没有内容召回 → 新物品永远冷启不了**。

### 4.4 模型预估 — Content-based CTR Prediction

**核心思路**：用模型**先预估**新菜的 CTR / 完播率，根据预估值给曝光。

```
输入：内容特征（CV + ASR + NLP + 作者画像 + 发布时间 ...）
输出：预估完播率、预估点赞率
→ 如果预估值高 → 给更多曝光
→ 如果预估值低 → 少曝光甚至不推
```

这是抖音 / 快手内部"**冷启动评估模型**"在做的事。

## 5. 新店开业 — 系统冷启动

整个平台刚启动，**所有用户都是新的，所有物品都是新的，没有任何历史数据**。这是最难的场景。

### 真实案例

| 平台 | 系统冷启动怎么破 |
|---|---|
| **Netflix(1998)** | **租 50 部 DVD 让 200 名员工评分**，凑出**第一个 100k 评分**作为种子 |
| **Pinterest(2010)** | 创始人 Ben Silbermann **手动 curate 前 5000 个 pin**；早期靠"穿搭 / DIY 家居"垂类切入女性用户 |
| **小红书（2013）** | 从**海外购物攻略**切入；创始人圈子带动种子内容，靠 KOL 笔记打开口碑 |
| **抖音（2016）** | 借用今日头条已有的算法和用户数据；用**音乐 + 美少女 + 滤镜**三件套快速建立标签体系 |
| **TikTok(2017)** | **完全照搬抖音算法和模型**到海外，绕过冷启动 |
| **快手（2011）** | 从**GIF 工具**起家，靠工具积累的用户数据切到短视频 |

### 共同规律

1. **没有捷径**：必须 hands-on，**手动 curate 头部内容**
2. **切垂类**：先在某个细分领域做深（穿搭/家居/旅游），别一上来什么都做
3. **借势**：能借现有产品 / 数据 / 用户的就借，原地起家最难
4. **种子 KOL**：找几个**愿意"为爱发电"**的核心用户/创作者带动初期生态

## 6. 探索 vs 利用 — E&E 的本质

> 你去一家新餐厅，**只点招牌菜（利用 Exploit）** 还是 **冒险试新菜（探索 Explore）**？

这是冷启动里**最核心**的哲学问题。

| 策略 | 描述 | 缺点 |
|---|---|---|
| **纯利用** | 永远推用户已知喜欢的 | **回音室**：用户兴趣越来越窄；新菜永无出头之日 |
| **纯探索** | 永远随机推 | 用户体验崩盘，立刻流失 |
| **E&E 平衡** ⭐ | 大部分利用 + 少量探索 | **唯一正解** |

### 几个经典平衡算法(人话版)

#### ε-greedy

```
ε = 0.1 → 90% 推已知最好的 + 10% 随机试
```

最简单，最常用。

#### UCB(Upper Confidence Bound)

```
"优先推不确定性大的（信息量大）"
推一个推过 1 次的电影 > 推一个推过 1000 次的（因为前者数据少，更需要测试）
```

#### Thompson Sampling

```
"按'可能很好的概率'抽签推"
每个候选物品维护一个概率分布，按分布抽样
雅虎 2010 年新闻推荐 CTR +12.8% 就是用这个
```

### 真实业务里,E&E 怎么落地

```
召回阶段：留 1-2 路专门做探索（随机召回、长尾召回）
排序阶段：在 top-K 里强制注入 5%~10% 的"低分但有潜力"候选
重排阶段：强制多样性（不让同类目占比 > 50%）
```

## 7. 冷启动在系统架构里的位置

**冷启动不是独立模块**，它**渗透在召回 / 排序 / 重排所有阶段**：

```
        ┌──────────────────────────────────────────────┐
        │              请求进来                          │
        └──────────────────────────────────────────────┘
                          │
                          ▼
        ┌──────────────────────────────────────────────┐
        │  召回                                          │
        │  ├── ItemCF (老用户主力)                       │
        │  ├── 双塔 (老用户主力)                          │
        │  ├── 热门召回 (新用户兜底) ⭐ 冷启动专用            │
        │  ├── 内容召回 (新物品兜底) ⭐ 冷启动专用            │
        │  └── 关注/作者召回 (新物品次要) ⭐ 冷启动专用       │
        └──────────────────────────────────────────────┘
                          │
                          ▼
        ┌──────────────────────────────────────────────┐
        │  排序                                          │
        │  └── 模型给所有候选打分                          │
        │       (新候选用 content-based 预估，无行为也能打分) │
        └──────────────────────────────────────────────┘
                          │
                          ▼
        ┌──────────────────────────────────────────────┐
        │  重排                                          │
        │  ├── 多样性 (新物品保护性强制曝光) ⭐ 冷启动专用     │
        │  └── E&E 注入 (5~10% 探索) ⭐ 冷启动专用           │
        └──────────────────────────────────────────────┘
```

## 8. 怎么评估冷启 — "测不准原理"

**冷启动的离线评估几乎不可能**，原因：

```
训练数据：都是 hot 用户 + hot 物品的历史行为
评估数据：你想测的是 cold 用户 + cold 物品
→ 训练分布跟评估分布完全不同 → 离线 metric 跟线上完全脱钩
```

### 业界主要靠**线上 A/B 测**

```
小流量切分两个桶：
  桶 A：用现有冷启策略
  桶 B：用新冷启策略

只看"新用户 + 新物品"的指标：
  - 新用户次日留存率
  - 新物品首次互动率
  - 新创作者粉丝增长率
```

这些是**冷启动专用指标**，跟全平台 GMV / DAU 不一样。

## 9. recsys-mini 的冷启状态

**ML-1M 数据集本身没有冷启动**（k-core 过滤已经把所有 user/item 的最少交互拉到 ≥ 20）。

但可以**模拟**：

```
模拟"新用户"：
  把某个用户的后半段历史删掉，看模型用前半段能不能猜对

模拟"新物品"：
  把某部电影的所有交互删掉，让它变成 zero-history
  看内容召回（用 title + genres）能不能找回相似电影
```

### 路线图

| 优先级 | 工作 |
|---|---|
| ⭐⭐⭐ | 实现内容召回（电影标题 word2vec / 类型 multi-hot 倒排）→ 解决物品冷启 |
| ⭐⭐ | 实现模拟"新用户"评估管线 |
| ⭐ | 实现 ε-greedy 召回路 → 解决用户冷启 |

## TL;DR — 三句话

1. **冷启动不是 bug，是日常呼吸**。
   TikTok 每秒 1,400 个新物品，每秒几十个新用户——所有平台都在解决这个问题。

2. **三种"新"，三套打法**：
   - 新用户 → onboarding + look-alike + Bandit 探索
   - 新物品 → 强制曝光 + 作者传播 + 内容召回 + 模型预估
   - 新平台 → 手动 curate + 切垂类 + 借势 + 种子 KOL

3. **E&E 是冷启动的灵魂**。
   宁愿前 50 次曝光"投资"(探索)，别为眼前的 CTR 牺牲长期生态。
