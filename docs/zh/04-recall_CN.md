## 一句话理解

> 召回 = 推荐系统里的"**婚介所**"。从全城 **1 亿个单身候选**里，**几十毫秒**帮你筛出 **200 个潜在匹配**，交给后面的"媒人"（排序）精挑细选。
>
> **它管"不能漏掉真命天子"，不管"谁更合适"——那是媒人的活。**
>
> 一旦婚介所没把对的人放进 200 个名单里，**后面再聪明的媒人也救不回来**。

---

## 1. 召回在整个系统里的位置（漏斗）

```
全城单身       婚介所       媒人       你妈       约会
 1 亿人  ───►  200 人  ───►  10 人  ───►  3 人  ───►  最后选 1 个
        召回         排序        重排
        "不漏"        "选对"     "兜底/调味"
```

| 阶段 | 干啥 | 关心 |
|---|---|---|
| 召回 | 大海捞针，**从 10⁸ 选 10³** | 真命天子在不在 200 人名单里？ |
| 排序 | 200 人里精挑 10 人 | 谁更合适？打分排序 |
| 重排 | 加多样性 / 加广告 / 去重 | 别让 10 个都是同一类型 |

**关键洞察**：召回这步只问"**在不在候选集里**"，**根本不在乎排第 1 还是排第 200**。这就是它跟排序的本质区别。

## 2. 召回的 3 个 KPI = 红娘的 3 个考核

| KPI | 红娘语言 | recsys-mini 实测 |
|---|---|---|
| **Recall@K** | "你给我 200 人，真命天子在里面吗？" | **50.20%**（每 2 个用户里有 1 个的真爱被捞中） |
| **Coverage@K** | "整个候选库你用了多少？还是只反复推那几个网红？" | **69.36%**（70% 的电影至少出现在某人的候选里） |
| **Latency** | "给我 200 人，能不能 50ms 内出？" | 现在还没上线 |

> **注意**：召回**不评 NDCG**——排序会把 200 人全打散重排，你召回内部排第几，根本不重要。

## 3. 8 大召回家族 = 8 种"红娘流派"

每种都是真实业务里的一类召回算法：

| # | 红娘流派 | 推荐术语 | 干啥 |
|---|---|---|---|
| 1 | **口碑老媒人** | CF（协同过滤） | "跟你品味相同的客户，最近跟谁对上眼了 → 也介绍给你" |
| 2 | **性格测试婚介** | **双塔（向量召回）** ⭐ | 双方都填问卷转成"性格向量"，向量近的就匹配 |
| 3 | **朋友的朋友** | 图召回（LightGCN） | 通过"朋友的朋友"链路找潜在对象 |
| 4 | **标签速配** | 倒排召回（tag） | 你说"喜欢户外、北京、文艺"，三个标签的人立刻调出来 |
| 5 | **朋友推荐** | 关注 / 社交召回 | 你关注的人发的新内容，直接推 |
| 6 | **场景红娘** | 上下文召回（LBS） | 同城、周末、雨天 → 推室内活动 |
| 7 | **保底兜底** | 热门召回 | 啥都失败时，给你看本月相亲爆款 |
| 8 | **新人专属** | 冷启动召回 | 新用户 / 新候选，用 Bandit、look-alike 等专门策略 |

> **真实平台同时跑 6–12 种**——每种擅长不同场景，**互相补盲**。详见 [`02-cold-start.md`](../en/02-cold-start.md) 中关于冷启动召回的部分。

## 4. 三个最核心的玩法，用大白话讲清楚

### 4.1 ItemCF — "口碑老媒人"

```
逻辑：
  "你之前跟小红、小绿都看对了眼"
  "刚好新客户小蓝跟小红、小绿气质很像"
  "→ 介绍小蓝给你"
```

**完全不看小蓝长啥样、做什么工作**——只看"**历史上有没有跟小蓝看对眼的，跟你品味相似**"。

公式 1 行就能写：

```
小红和小绿有多像  =  「同时跟两人都对眼过的客户数」 / √（喜欢小红的人 × 喜欢小绿的人）
```

**致命弱点**：新候选还没人跟他/她相过亲 → 算不出相似度 → **永远召不出来**（冷启动）。

### 4.2 双塔 — "性格测试婚介"

```
用户塔  →  把你（年龄、收入、爱好、最近看过的人）→ 压成 128 个数字（向量）
物品塔  →  把每个候选（性别、年龄、行业、自我介绍）→ 也压成 128 个数字

  把两个向量塞进同一个"相亲会场"（同一个向量空间）
        ↓
  向量靠得近 = 越匹配
```

**训练目标**：让"历史上对上眼的两人"向量靠近，没对眼的离远。

**关键设计**：两个塔**互相不能偷看**对方的资料——否则你就没法**离线**把全城候选的向量都算好。一旦"得看见你才能算出我的向量"，1 亿候选每次都要重算，**毫秒级响应做不到**。

```
离线（每晚跑一次）：
  → 把 1 亿候选的向量都算好，建索引

在线（你刷新一次）：
  → 算一下"你"的向量（你的塔，毫秒级）
  → 去索引里找最近的 200 个向量
  → 完成，p99 < 30ms
```

> **为什么这是工业界标准**：YouTube DNN 2016 年提出，10 年了基本没换过框架。

### 4.3 ANN — "婚介所的卡片柜"

```
问题：1 亿张候选卡片，你拿一张"你"的卡片去找最像的 200 张
  暴力法：1 亿张卡片一张张比 → 几分钟 → 不可能
  ANN 法：先按"楼层 → 分类 → 货架"导航 → 只跟某个小货架的卡片比 → 30ms 搞定
```

**代价**：偶尔会漏掉真正最相似的（比如它在另一个货架）。

**收益**：**1000 倍**速度提升。**99% 召得到** vs **100% 但慢 1000 倍**——业务永远选前者。

主流算法：**HNSW**（最常用）、**IVF + PQ**（最省内存）、**FAISS**（最常用的库）。

## 5. 多路融合 — "请 6 个红娘并行选人"

### 为啥不能只靠 1 个红娘？

| 你的真实需求 | 单一红娘的盲区 |
|---|---|
| 我朋友刚加入婚介所，请介绍他 | 老媒人没数据，介绍不了 |
| 我从没相过亲，对啥都不排斥 | 老媒人束手无策 |
| 这个月全国最火的"网红"对象 | 个性化匹配可能漏 |
| 周末 / 下雨 / 我在外地 | 静态匹配感知不到 |

### 怎么融合 6 个红娘的名单？

最常用是 **RRF**（也是 recsys-mini 现在在用的）：

```
每个候选的最终分  =  Σ  1 / (60 + 它在第 N 个红娘的排名)
```

> 翻译人话：**只看每个红娘把你排第几，不看打了几分**。这样不同红娘的"打分体系"不一致也不影响。

## 6. 三个最常踩的评估坑

### 坑 1：召回阶段看 NDCG 没意义

```
召回只问"在不在 200 人里"
NDCG 是"排第几"
→ 你召回内部排第几，排序会全部打散重新排
→ 看 NDCG 等于自欺欺人
```

**正确做法**：召回阶段只看 `Recall@K + Coverage`。

### 坑 2：Coverage 高 ≠ 候选多样

```
6,000 个用户，每人 200 个候选
总共覆盖 70% 的物品  ← 看似不错
但每个用户的 200 个候选可能高度雷同  ← 用户体验仍然单调
```

**正确指标**：要看 **每个用户列表内的 ILD**（Intra-List Diversity）。

### 坑 3：K 一变，指标就不可比

```
A 模型 Recall@10  = 6%
B 模型 Recall@200 = 50%
→ 这不能比！K 不一样
```

**铁律**：对比模型，**K 必须固定**。这是最常见的"伪提升"陷阱。

## 7. 一个隐藏的大坑 — SSB

**SSB = Sample Selection Bias（样本选择偏差）**。

**场景**：

```
昨天：婚介所只用"老媒人 + 兜底"挑人
      → 媒人打分系统就是基于"这些候选"训练的

今天：你给婚介所升级了"性格测试匹配（双塔）"
      → 候选的分布完全变了（多了一堆从没见过的人）
      → 媒人之前训练的打分体系不再适用
      → 排序质量暴跌
```

**解决**：**任何一次召回升级，都必须重新训练排序**。这是 recall ↔ ranking 的"耦合契约"，跑不掉。

## 8. recsys-mini 当前状态

```
召回路线：
  ItemCF + Popular  →  RRF 融合  →  Recall@200 = 50.20%
```

| 排名 | 下一步要做的 | 期待收益 | 工作量 |
|---|---|---|---|
| ⭐⭐⭐ | 上**双塔召回**（DSSM + FAISS） | Recall@200 → 60%+ | 3–5 天 |
| ⭐⭐⭐ | 上**内容召回**（用电影标题做 NLP 向量） | 解决冷门电影召不出的问题 | 1–2 天 |
| ⭐⭐ | 把"是哪个召回路出的"作为排序特征 | 不动召回也能提升排序 | 半天 |
| ⭐⭐ | 学习式融合替代 RRF | 突破现在的 RRF 上限 | 1 天 |

## TL;DR — 三句话

1. **召回 = 婚介所，排序 = 媒人**。
   召回宁可多发 200 张门票（高 Recall@K），也别漏掉真命天子（漏了排序救不回来）。

2. **现代召回 = 双塔 + ANN 是主力**。
   双塔把用户和物品都压成向量，ANN 让 1 亿候选里秒找 200。这是过去 10 年没变过的工业界标配。

3. **多路并行召回 + RRF 融合 + 重训排序，是一套"系统工程"**。
   没有一种召回路能 cover 所有需求，所以平台同时跑 6–12 路。每次召回改了，**排序必须重训**——这是 SSB 的铁律。
