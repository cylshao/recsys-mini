## 一句话理解

> 推荐系统的数据集 = **病人**。
>
> 这份文档 = 给 **MovieLens-1M** 做的全身体检报告。
>
> **你必须先体检，才知道它哪里"健康"（可以学算法）、哪里"残疾"（学不来真实业务）、该开什么"药"（怎么预处理）。**

跳过这一步直接上算法，等同于不看病史就开刀——算法跑得再花哨，结果也对不上真实业务的因果。

---

## 1. 病人是谁，谁在体检

| | 内容 |
|---|---|
| **病人** | MovieLens-1M：2000~2003 年某个美国大学的电影评分网站 3 年的"借阅记录" |
| **科室** | 推荐系统数据特性科 |
| **体检 12 项** | 评分分布 / 时间分布 / 用户活跃度 / 物品长尾 / 稀疏度 / 性别 / 年龄 / 职业 ... |
| **病情严重程度** | "代码学习用"是优秀健康；"模拟真实业务"是中风偏瘫 |

> **跟今天的快手 / 小红书 / Pinterest 比，ML-1M 是 1995 年的国民身高曲线 vs 2026 年的实时心率手表数据。**

---

## 2. 基本面（身高体重）

| 指标 | 数值 | 类比 |
|---|---|---|
| 用户数 | **6,040** | 一个 6,000 人的小镇 |
| 电影数 | **3,883** | 一家中型 DVD 出租店的库存 |
| 评分数 | **1,000,209** | 3 年累积 100 万条"打星" |
| 评分制 | 1-5 整数星 | 像今天的"豆瓣评分" |
| 时间范围 | 2000-04 ~ 2003-02 | 一段 3 年的时间窗 |
| 一个用户平均 | **166 次评分** | 3 年看了 166 部 → 平均一周 1 部 |
| 一部电影平均 | **270 次被评** | 每部都有"几百人看过"作为底子 |

> **跟今天比对**：
> - 快手 / 抖音单用户日均刷 **100+ 视频**，一周相当于 ML-1M 用户**整整 3 年**
> - 小红书 / Pinterest 月活几亿，候选物品几十亿，ML-1M 整个数据库 = 抖音几个小时的新发

## 3. 评分分布 — 第一项体检指标

| 评分 | 占比 | 红心翻译 |
|---|---|---|
| ★ | 5.6% | "看完想砸电视" |
| ★★ | 10.7% | "不太行" |
| ★★★ | 26.1% | "**还行吧**"（敷衍打分） |
| **★★★★** | **34.9%** | "**挺好的**" ← 正样本主力 |
| **★★★★★** | **22.7%** | "**真心爱**" ← 强信号 |

**4-5 分加起来 = 57.6%** → 这就是为什么 `02_prepare_samples.py` 把 `positive_threshold = 4`：

> **57.6% 的样本被采纳，42.4% 的"敷衍打分"被剔除**。一半多一点，强信号 + 数据量之间最优平衡。

---

## 4. 时间分布 — 致命的"心电图异常"

体检最异常的指标。看下面这张图：

```
评分量（万）
   30 │      ████
   25 │      ████
   20 │      ████
   15 │      ████
   10 │      ████  ██
    5 │ ▄▄   ████  ██  ▄▄   ▄▄
       └─────────────────────────►
       2000   2001    2002   2003
```

**2000 年 11 月一个月吃下了 30% 的数据**。其余 35 个月加起来才占剩下 70%。

为什么？因为 ML-1M 不是"用户每天追剧"，而是"网站发券给大学生做问卷，做完一次性补打几十部电影"。

**这导致一个致命后果**：

```
如果按"全局时间"切分（最后 7 天做测试集）：
  → test 集就只剩 ~30 个用户
  → Recall@K 方差爆炸
  → 模型对比毫无意义
```

→ 这是 `02_prepare_samples.py` 选 **LOO（leave-one-out）** 而不是 time-split 的根本原因。

> **对比快手 / TikTok / YouTube Shorts**：实时日志，每天 24h 均匀分布，time-split 是标配。
> **对比小红书 / Pinterest**：用户每天保存几个 pin / 收藏几篇笔记，时间分布也比 ML-1M 平滑得多。

## 5. 用户行为长度 — 全是"老观众"

| 指标 | 数值 | 说明 |
|---|---|---|
| 用户最少交互 | **20** | 数据集出厂保证，强制 k-core=20 |
| 用户最多交互 | **2,314** | 重度狂热影迷 |
| 用户平均 | **166** | 大部分用户都活跃 |
| 中位数 | **96** | 半数用户看过 100 部左右 |

**关键事实**：**ML-1M 没有"游客用户"**——所有用户都是"看过 ≥20 部电影"的活跃户。

```
现实中的快手 / 抖音 / 小红书：
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  90% 是"轻量用户"（看 < 10 个视频就走）   ← ML-1M 一个都没有
   8% 是"中度用户"
   2% 是"重度用户"
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MovieLens-1M：
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  100% 都是"重度+中度用户"                ← 离真实世界太远
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

→ **这意味着冷启动用户问题在 ML-1M 里根本不存在**。你想研究"新用户怎么推"，必须用 KuaiRand 或者手动模拟。

## 6. 物品长尾 — 教科书级别的二八

| 指标 | 数值 | 说明 |
|---|---|---|
| 物品最少交互 | **1** | 只被 1 人评过的孤儿电影 |
| 物品最多交互 | **3,428** | **TOP1 被 56.8% 用户看过** |
| 平均 | **270** | 大头都集中在头部 |

**TOP10 电影都是经典**：

| 排名 | 电影 | 被多少用户评过 |
|---|---|---|
| 1 | American Beauty (1999) | 3,428 |
| 2 | Star Wars: Episode IV (1977) | 2,991 |
| 3 | Star Wars: Episode V (1980) | 2,990 |
| 4 | Star Wars: Episode VI (1983) | 2,883 |
| ... | ... | ... |

**TOP1 的 56.8% 渗透率**——意味着随机抓一个用户，**一半多的概率看过《American Beauty》**。

> **这种"全平台爆款"分布**：
> - 抖音的 24h 爆款视频 ✓ 类似
> - 小红书的"全网热门笔记" ✓ 类似
> - YouTube Shorts 的病毒视频 ✓ 类似
> - 跟现实的"二八定律"完全吻合

**长尾电影的孤独**：

```
评分人数  >= 100   :  约 1,800 部 (50%)
评分人数  20 ~ 99 :  约 1,400 部 (38%)
评分人数  <  20   :  约   400 部 (10%)
评分人数  ==  1   :    数百部     (孤儿)
```

→ 协同过滤（ItemCF）对这些"孤儿电影"完全无能为力，**这就是为啥需要"内容召回"做兜底**。

## 7. 矩阵稀疏度 — 跟真实平台差 4500 倍

```
ML-1M 矩阵稠密度：
  100 万评分 / (6,040 用户 × 3,706 电影) ≈ 4.47%

→ 大致是：100 个用户-电影格子里，4-5 个有评分
```

**这已经算"非常稠密"了**——因为数据集本身做了 k-core 过滤。

对比真实业务：

| 平台 | 矩阵稠密度 | 差几倍 |
|---|---|---|
| MovieLens-1M | **4.47%** | 基准 |
| 网易云音乐 | ~0.1% | 稀 45 倍 |
| 小红书笔记 | ~0.01% | 稀 450 倍 |
| **抖音 / 快手 / TikTok** | **< 0.001%** | **稀 4,500 倍** |
| Pinterest pin | ~0.001% | 稀 4,500 倍 |

**4,500 倍的稀疏度差距**意味着什么？

→ ML-1M 上跑得很好的 ItemCF，搬到抖音上**直接崩**（共现矩阵几乎全 0，算不出相似度）。
→ 这就是为啥工业界对长尾候选必须用**双塔 / GNN / 内容召回**而非纯 CF。

## 8. 跟今天的 UGC 平台横向对比

把 ML-1M 跟今天的主流平台拉出来对照，差距一目了然：

| 维度 | **MovieLens-1M** | **抖音 / 快手** | **YouTube Shorts** | **Pinterest** | **小红书** |
|---|---|---|---|---|---|
| 时间窗 | 3 年累积 | 滚动 30~90 天 | 30 天 | 长期累积 | 90 天 |
| 用户量 | 6K | **数亿 DAU** | **20 亿 MAU** | **5 亿 MAU** | **3 亿 MAU** |
| 物品量 | 4K | 亿级在库，每日新增千万 | 每分钟上传 500 小时 | 数百亿 pin | 数十亿笔记 |
| 用户日均交互 | 166 次 / 3 年 | 100+ 次 / 天 | 50+ 次 / 天 | 50+ pin 收藏 / 月 | 30+ 篇 / 天 |
| 稀疏度 | 4.47% | < 0.001% | < 0.001% | ~0.001% | ~0.01% |
| 反馈类型 | 1 种（5 星评分） | **10+ 种**（完播 / 点赞 / 评论 / 分享 / 关注 / 不感兴趣 / 二创 ...） | 10+ 种 | 5+ 种（保存 / 隐藏 / 点击 / 分享 ...） | 8+ 种（点赞 / 收藏 / 评论 / 关注 / 购买 ...） |
| 物品生命周期 | 永久（电影不会下架） | **90% 24h 内死亡** | 70% 7 天内消亡 | 永久存在 | 头部长尾兼具 |
| 实时性 | 无 | **秒级反馈循环** | 分钟级 | 小时级 | 分钟级 |
| 上下文 | 无 | 时间 / 地理 / 设备 / 网络 / 上一刷 | 同 | 偏好 / 设备 | 时间 / 地理 / 内容场景 |
| 内容特征 | 类型标签 | **CV+NLP+ASR 多模态嵌入** | 同 | **PinSage 图像 + 文本嵌入** | 多模态 + 商品图谱 |
| 社交图 | 无 | 关注 / 朋友 / 同城 | 频道订阅 | follow / board | 关注 / 互动图 |
| 冷启动 | **无**（k-core 过滤掉了） | **核心问题之一** | **核心问题** | **核心问题** | **核心问题** |

| | MovieLens-1M | 真实 UGC 平台 |
|---|---|---|
| 类比 | **一座老图书馆的借阅记录** | **24h 开放的菜市场** |
| 节奏 | 慢、稳定、可分析 | 快、混乱、瞬息万变 |
| 用途 | **学算法、跑 baseline** | **真实业务、真实用户、真金白银** |

## 9. 那为啥还要用 ML-1M

如果差这么多，为啥不直接上 KuaiRand / TikTok 公开数据？

| 原因 | 解释 |
|---|---|
| **学算法的"解剖蛤蟆"** | 医学生先解剖蛤蟆，不会直接做心脏移植。ML-1M 干净、可控、可复现 |
| **跑 baseline 不需要规模** | ItemCF / 双塔 / LightGBM 在 ML-1M 上跑 30 秒，KuaiRand 上要 30 分钟 |
| **学术界基准** | YouTube DNN / SASRec / EASE 等论文都拿 ML-1M 当 benchmark，方便横向对比 |
| **隐私干净** | 不用担心包含个人信息，公开 20 年了 |
| **教学友好** | 数据量小、字段少、文档全 |

**正确姿势**：把 ML-1M 当"入门用的玩具数据集"，**学会算法本身**；想要做真业务，再切到 KuaiRand / MIND。

## 10. 体检完了 → 怎么"开药"（预处理决策）

体检完，必须根据病情**对症下药**。这就是 `02_prepare_samples.py` 在做的事：

| 体检发现 | 处方 | 设定值 |
|---|---|---|
| 用户行为长度都 ≥ 20，没游客 | k-core 保留 5/5 即可 | `min_user_inter=5` |
| 4-5 分占 57.6%，是真信号 | 用 ≥4 分作正样本 | `positive_threshold=4` |
| 时间分布严重不均（§4） | **必须用 LOO，不能 time-split** | `split_strategy=loo` |
| LOO 可能漏 unseen user/item | 用 `filter_eval_users` 兜底 | 默认开 |

> **详细决策依据**：[`01-data-source-analysis.md` §13](../en/01-data-source-analysis.md#13-preprocessing-decisions-baked-into-02_prepare_samplespy)（英文版）

## TL;DR — 三句话

1. **ML-1M = 一个小镇 3 年的电影院记录**。6K 用户 / 4K 电影 / 1M 评分。
   出厂保证 k-core=20，无冷启动，矩阵 4.47% 稠密（比抖音稠密 4,500 倍）。

2. **它有两个致命的"体检异常"**：
   - 时间分布 30% 数据扎堆在 2000-11 → **必须 LOO，不能 time-split**
   - 没有游客用户 → **学不到真正的冷启动问题**

3. **它的最佳用途**：
   **解剖蛤蟆**——学算法、跑 baseline、对齐学术论文。**别拿它推 prod**。
